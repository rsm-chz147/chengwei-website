Introduction

Blueprinty is a small software firm that builds tools for preparing patent application blueprints for the US patent office. Its marketing team would like to make a strong claim: engineering firms that use Blueprinty’s software are more successful at getting patents approved.

The tempting marketing story is simple: Blueprinty customers win more patents. The statistical question is more demanding: does that advantage still appear after comparing customers to similar non-customers?

That claim is not as simple to evaluate as it sounds. The ideal dataset would follow the same firms before and after they adopted Blueprinty’s software, allowing us to compare each firm’s patent outcomes against its own past performance. We do not have that kind of before-and-after evidence. Instead, Blueprinty has collected cross-sectional data on 1,500 mature engineering firms. For each firm, the data record the number of patents awarded in the last five years, the firm’s region, age since incorporation, and whether it is a Blueprinty customer.

Because firms do not become Blueprinty customers at random, a raw comparison of customers and non-customers could be misleading. If Blueprinty customers are older, concentrated in more patent-heavy regions, or otherwise different from non-customers, then a higher patent count among customers may reflect those differences rather than the software itself. The goal of this analysis is therefore to model patent counts while adjusting for observed firm characteristics.

A Simple Poisson Model via Maximum Likelihood

The outcome variable is a count. Patent awards cannot be negative, and they must be integer-valued, so a Normal model is not a natural starting point. A Poisson model is a standard first model for non-negative count outcomes.

Let \(Y_i\) be the patent count for firm \(i\), and begin with the simplest possible model:

\[ Y_i \sim \text{Poisson}(\lambda). \]

For one observation,

\[ f(Y_i|\lambda) = \frac{e^{-\lambda}\lambda^{Y_i}}{Y_i!}. \]

Assuming observations are independent and identically distributed, the joint likelihood is

\[ L(\lambda|Y_1,\ldots,Y_n) = \prod_{i=1}^{n}\frac{e^{-\lambda}\lambda^{Y_i}}{Y_i!}. \]

Taking logs gives the log-likelihood:

\[ \ell(\lambda) = \sum_{i=1}^{n}\log \left(\frac{e^{-\lambda}\lambda^{Y_i}}{Y_i!}\right) = \sum_{i=1}^{n}\left(-\lambda + Y_i\log\lambda - \log(Y_i!)\right). \]

The final term does not depend on lambda, but it is still useful to keep in the code because it gives the actual log-likelihood value.

Code 
def poisson_loglikelihood(lam, y):
    if lam <= 0:
        return -np.inf
    return np.sum(y * np.log(lam) - lam - np.array([math.lgamma(v + 1) for v in y]))

The simple Poisson log-likelihood peaks at the sample mean

The peak of this curve is the maximum likelihood estimate. Visually, the log-likelihood reaches its maximum around lambda = 3.68, which is the sample mean number of patents.

We can also see this analytically. Differentiating the log-likelihood gives

\[ \frac{\partial \ell}{\partial \lambda} = \sum_{i=1}^{n}\left(-1 + \frac{Y_i}{\lambda}\right) = -n + \frac{\sum_{i=1}^{n}Y_i}{\lambda}. \]

Setting the derivative equal to zero:

\[ -n + \frac{\sum_{i=1}^{n}Y_i}{\lambda} = 0 \quad \Rightarrow \quad \hat{\lambda}_{MLE} = \frac{1}{n}\sum_{i=1}^{n}Y_i = \bar{Y}. \]

This result makes intuitive sense because the mean of a Poisson distribution is lambda.

Code 
def maximize_simple_poisson_newton(y, initial_lam=1.0, tolerance=1e-10, max_iter=100):
    lam = initial_lam
    for _ in range(max_iter):
        gradient = -len(y) + y.sum() / lam
        hessian = -y.sum() / (lam ** 2)
        next_lam = lam - gradient / hessian
        if abs(next_lam - lam) < tolerance:
            return next_lam
        lam = next_lam
    return lam

if importlib.util.find_spec("scipy") is not None:
    from scipy import optimize

    simple_optim = optimize.minimize(
        fun=lambda eta: -poisson_loglikelihood(np.exp(eta[0]), y),
        x0=np.array([0.0]),
        method="BFGS"
    )
    numerical_lambda = float(np.exp(simple_optim.x[0]))
    optimizer_used = "scipy.optimize.minimize"
else:
    numerical_lambda = maximize_simple_poisson_newton(y)
    optimizer_used = "Newton fallback"

simple_results = pd.DataFrame({
    "Method": [optimizer_used, "Sample mean"],
    "Lambda hat": [numerical_lambda, y.mean()]
})

show_table(simple_results, caption="Simple Poisson MLE compared with the sample mean", decimals=4)

The numerical optimizer and the sample mean match because, in the one-parameter Poisson model, the sample mean is the closed-form maximum likelihood estimate.

Poisson Regression

The simple model assumes every firm has the same expected patent count. That is too restrictive here because firms differ in age, region, and customer status. A Poisson regression lets the expected count vary by firm:

\[ Y_i \sim \text{Poisson}(\lambda_i), \qquad \lambda_i = \exp(X_i'\beta). \]

The exponential inverse link is important. The linear index X beta can be any real number, but lambda must be positive. Exponentiating the linear index keeps the predicted patent rate on the positive real line.

Code 
def poisson_regression_loglikelihood(beta, y, X):
    eta = X @ beta
    lam = np.exp(np.clip(eta, -50, 50))
    return np.sum(y * np.log(lam) - lam - np.array([math.lgamma(v + 1) for v in y]))

The model matrix includes an intercept, age, age squared, region indicators, and customer status. I include age squared because the relationship between firm age and patenting is unlikely to be perfectly linear: patenting may rise as firms mature and then flatten or decline. One region must be omitted because the intercept plus a full set of region indicators would be perfectly collinear. I use Midwest as the reference region.

def fit_poisson_newton(y, X, tolerance=1e-10, max_iter=100):
    beta = np.zeros(X.shape[1])
    for _ in range(max_iter):
        eta = X @ beta
        mu = np.exp(np.clip(eta, -50, 50))
        gradient = X.T @ (y - mu)
        hessian = -(X.T * mu) @ X
        step = np.linalg.solve(hessian, gradient)
        beta_next = beta - step
        if np.max(np.abs(beta_next - beta)) < tolerance:
            beta = beta_next
            break
        beta = beta_next

    mu = np.exp(np.clip(X @ beta, -50, 50))
    hessian = -(X.T * mu) @ X
    covariance = np.linalg.inv(-hessian)
    standard_errors = np.sqrt(np.diag(covariance))
    return beta, standard_errors

def poisson_observed_se(beta, y, X):
    mu = np.exp(np.clip(X @ beta, -50, 50))
    hessian = -(X.T * mu) @ X
    covariance = np.linalg.inv(-hessian)
    return np.sqrt(np.diag(covariance))

if importlib.util.find_spec("scipy") is not None:
    from scipy import optimize

    poisson_optim = optimize.minimize(
        fun=lambda beta: -poisson_regression_loglikelihood(beta, y, X),
        x0=np.zeros(X.shape[1]),
        method="BFGS"
    )
    beta_hat = poisson_optim.x
    se_hat = poisson_observed_se(beta_hat, y, X)
    regression_optimizer_used = "scipy.optimize.minimize"
else:
    beta_hat, se_hat = fit_poisson_newton(y, X)
    regression_optimizer_used = "Newton fallback"

mle_table = pd.DataFrame({

The manually optimized estimates should match the statsmodels GLM estimates very closely when statsmodels is available. Small differences in standard errors can occur because the hand-coded version uses the observed information matrix from the Hessian, while GLM software uses its own fitting routine and information matrix calculations.

The customer coefficient is positive: about 0.208. Because the Poisson regression uses a log link, exponentiating this coefficient gives a rate ratio of about 1.23. Holding age and region fixed, the model estimates that Blueprinty customers have an expected patent count about 23% higher than comparable non-customers. In business terms, the association is not just statistically visible; it is large enough to matter for a marketing claim.

The age pattern is also sensible. The age coefficient is positive while the age-squared coefficient is negative, which suggests patenting increases with firm age but at a decreasing rate. Older firms appear to gain from experience and accumulated resources, but the quadratic term suggests those gains flatten out rather than increasing forever. The region coefficients are relatively small after controlling for customer status and age, which makes the customer result easier to interpret than the raw customer/non-customer comparison.

The Effect of Blueprinty’s Software

Coefficients from a Poisson regression are multiplicative, so the customer coefficient is not directly measured in additional patents. To express the result in patent-count units, I construct two counterfactual datasets:

  1. X0: every firm is treated as a non-customer.
  2. X1: every firm is treated as a customer.

Age and region stay fixed at each firm’s observed values. The only thing that changes is customer status.

Under the fitted model, the average predicted patent count is about 3.44 if every firm is treated as a non-customer and about 4.23 if every firm is treated as a Blueprinty customer. The average difference is about 0.79 patents per firm over five years, holding age and region fixed. Since the average firm in the sample receives fewer than four patents over five years, an increase of roughly 0.8 patents is practically meaningful, not just a tiny numerical difference.

For Blueprinty’s marketing team, the strongest defensible claim is not that the software has been proven to cause more patent approvals. A better claim is that, among mature engineering firms with similar age and regional profiles, Blueprinty customers are associated with meaningfully higher patent counts. That distinction matters: the model adjusts for observed differences in age and region, but it cannot adjust for unobserved differences such as firm size, R&D budget, legal resources, management quality, or the quality of a firm’s patent pipeline.
