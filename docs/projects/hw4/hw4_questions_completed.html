Introduction

MaxDiff, also called Best-Worst Scaling, is a survey method for measuring relative preferences. Instead of asking people to rate every item on a numeric scale, each respondent sees a small set of items and chooses the one they like most and the one they like least. This makes the task a direct trade-off: respondents must reveal which options win and lose when placed against alternatives.

That trade-off structure is useful because numeric rating scales are often hard to compare across people. A “7” from one person may mean something different from a “7” from another person. MaxDiff avoids some of that scale-use bias by forcing differentiation within each task.

In this assignment, the items are the core MSBA classes at UCSD Rady. I estimate class preferences three ways. First, I use a simple counts score based on how often each class was picked best minus how often each class was picked worst. Second, I fit a multinomial logit (MNL) model by maximum likelihood. Third, I fit the same MNL model using a Bayesian random-walk Metropolis-Hastings sampler. The three methods should agree on the broad ranking, especially at the top and bottom, while differing in how they quantify uncertainty.

Counts Analysis

The counts analysis is a simple descriptive summary. For each item, I count how many times it was shown, how many times it was selected as best, and how many times it was selected as worst. The score is the percentage best minus the percentage worst:

\[ \text{score}_j = \%\text{best}_j - \%\text{worst}_j. \]

A higher score means the class tends to win when shown. A lower score means the class tends to lose when shown.

From MaxDiff Data to MNL Choices

The MNL model treats each MaxDiff task as a pair of choice observations. First, the respondent chooses the best item from the four shown items. If the shown set is \(\{a,b,c,d\}\), the probability of choosing item \(b\) as best is

\[ P(\text{best}=b) = \frac{\exp(\beta_b)} {\exp(\beta_a)+\exp(\beta_b)+\exp(\beta_c)+\exp(\beta_d)}. \]

Then, after the best item is removed, the respondent chooses the worst item from the remaining three. The worst choice is modeled by flipping the utilities:

\[ P(\text{worst}=c \mid \text{best}=b) = \frac{\exp(-\beta_c)} {\sum_{j \in \text{shown} \setminus \{b\}} \exp(-\beta_j)}. \]

Only differences in utilities are identified, so I normalize \(\beta_1 = 0\) and estimate the remaining nine coefficients.

MNL via Maximum Likelihood

The log-likelihood over all tasks is

\[ \ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \left[ \beta_{j_b^*} - \log \sum_{j \in \text{shown}}\exp(\beta_j) - \beta_{j_w^*} - \log \sum_{j \in \text{shown}\setminus \{j_b^*\}}\exp(-\beta_j) \right]. \]

    remaining_items[i] = shown_items[i, shown_items[i] != best_items[i]]

def full_beta(beta_free):
    return np.r_[0.0, np.asarray(beta_free, dtype=float)]

def ll_and_grad(beta_free):
    beta = full_beta(beta_free)
    grad_full = np.zeros(10)

    v = beta[shown_items]
    m = v.max(axis=1, keepdims=True)
    ev = np.exp(v - m)
    p = ev / ev.sum(axis=1, keepdims=True)
    ll_best = beta[best_items] - (m[:, 0] + np.log(ev.sum(axis=1)))

    np.add.at(grad_full, best_items, 1)
    for col in range(4):
        np.add.at(grad_full, shown_items[:, col], -p[:, col])

    v_worst = -beta[remaining_items]
    m_w = v_worst.max(axis=1, keepdims=True)
    ev_w = np.exp(v_worst - m_w)
    p_w = ev_w / ev_w.sum(axis=1, keepdims=True)
    ll_worst = -beta[worst_items] - (m_w[:, 0] + np.log(ev_w.sum(axis=1)))

    np.add.at(grad_full, worst_items, -1)
    for col in range(3):
        np.add.at(grad_full, remaining_items[:, col], p_w[:, col])

    return float(np.sum(ll_best + ll_worst)), grad_full[1:]

def ll(beta_free):
    return ll_and_grad(beta_free)[0]

The next function is a small BFGS optimizer written directly in Python. This avoids relying on R or on scipy, while following the same maximum-likelihood logic as optim(..., method = "BFGS") in R.

Code 
def bfgs_maximize(x0, max_iter=500, tol=1e-7):
    x = np.asarray(x0, dtype=float).copy()
    k = len(x)
    B = np.eye(k)
    f, g = ll_and_grad(x)

    for iteration in range(max_iter):
        if np.linalg.norm(g) < tol:
            break

        try:
            direction = np.linalg.solve(B, g)
        except np.linalg.LinAlgError:
            B = np.eye(k)
            direction = g.copy()

        if np.dot(g, direction) <= 0:
            B = np.eye(k)
            direction = g.copy()

        step = 1.0
        while step > 1e-10:
            x_new = x + step * direction
            f_new, g_new = ll_and_grad(x_new)
            if f_new >= f + 1e-4 * step * np.dot(g, direction):
                break
            step *= 0.5

        s = x_new - x
        y = -(g_new - g)
        Bs = B @ s

        if np.dot(y, s) > 1e-10 and np.dot(s, Bs) > 1e-10:
            B = B + np.outer(y, y) / np.dot(y, s) - np.outer(Bs, Bs) / np.dot(s, Bs)
        else:
            B = np.eye(k)

        x, f, g = x_new, f_new, g_new

    return {"par": x, "value": f, "grad": g, "hessian_neg_approx": B, "iterations": iteration + 1}

mle_out = bfgs_maximize(np.zeros(9))

def negative_hessian_from_gradient(theta, eps=1e-4):
    theta = np.asarray(theta, dtype=float)
    k = len(theta)
    H = np.empty((k, k))

    for j in range(k):
        step = np.zeros(k)
        step[j] = eps
        _, grad_plus = ll_and_grad(theta + step)
        _, grad_minus = ll_and_grad(theta - step)
        H[:, j] = -(grad_plus - grad_minus) / (2 * eps)

    return (H + H.T) / 2

MNL via Bayesian Estimation

The Bayesian model uses the same likelihood as the MLE model, but combines it with a weakly informative normal prior:

\[ \boldsymbol{\beta} \sim N(\boldsymbol{0}, 10I). \]

I estimate the posterior using a random-walk Metropolis-Hastings sampler.

Code 
def log_post(beta_free):
    beta_free = np.asarray(beta_free, dtype=float)
    log_prior = np.sum(-0.5 * np.log(2 * np.pi * 10) - beta_free**2 / (2 * 10))
    return ll(beta_free) + log_prior

def mh(beta0, n_iter, step):
    beta = np.asarray(beta0, dtype=float).copy()
    draws = np.empty((n_iter, len(beta)))
    lp = log_post(beta)
    accept = 0

    for t in range(n_iter):
        beta_star = beta + np.random.normal(0, step, size=len(beta))
        lp_star = log_post(beta_star)

        if np.log(np.random.uniform()) < lp_star - lp:
            beta = beta_star
            lp = lp_star
            accept += 1

        draws[t] = beta

    return {"draws": draws, "accept_rate": accept / n_iter}

The advantage of the Bayesian version is that uncertainty for derived quantities, such as shares of preference, is straightforward: each posterior draw is transformed into shares, and the credible intervals come directly from those transformed draws. This is harder to do from the MLE estimates without an additional approximation such as the delta method or simulation from the asymptotic covariance matrix.

The counts method is easy to explain and useful as a first descriptive look. The MNL model adds a formal model of the choice process and uses information from the full choice set, not just the winning and losing counts. The Bayesian version adds a natural way to describe uncertainty for utility estimates and for transformed quantities such as shares of preference. In this application, the Bayesian model does not change the main conclusion, but it makes the uncertainty around the middle rankings more visible.

Discussion

Substantively, students in this sample appear to most prefer MGTA 495 Marketing Analytics. The result is not just a narrow first-place finish: MGTA 495 is far ahead under the simple counts score and under both versions of the MNL model. Business Analytics, Customer Analytics, and Large Data also perform well, but they are in a second tier rather than tied with Marketing Analytics. Analytics Consulting, the Marketing/Finance/Operations course, and AI Math/Programming/Analytics appear less preferred in this specific survey.

For a non-technical reader, the practical conclusion is that course preferences are not evenly distributed across the core curriculum. Students seem especially attracted to applied analytics classes with a direct link to marketing, customer analytics, and data work. By contrast, courses that may feel broader, more foundational, or less directly tied to a specific analytics career path receive weaker relative preference scores. This interpretation should be treated carefully because the survey measures relative preference, not course quality.

Methodologically, I would use counts analysis for a quick descriptive dashboard, MLE MNL when I need a rigorous point estimate with classical standard errors, and Bayesian MNL when I want credible intervals or want to extend the model to more complex settings such as individual-level heterogeneity. In this assignment, all three methods tell a consistent story, so the extra modeling mainly improves interpretation and uncertainty quantification rather than changing the headline result.

The main caveat is that this is a self-selected sample of MSBA students. Preferences may differ across cohorts, prior coursework, career goals, and timing in the program. A student who has already taken a class may answer differently from a student who only knows the title or instructor. If I had more time, I would explore whether preferences differ by background, career interest, and prior exposure to each course.
